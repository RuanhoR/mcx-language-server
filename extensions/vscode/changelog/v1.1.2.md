# v1.1.2 (2026-08-23)

### Features

- **Reuse VS Code's TypeScript**: The extension no longer bundles a ~20MB copy of TypeScript.
  - Client locates the SDK via `<appRoot>/extensions/node_modules/typescript/lib` (with an Eclipse-Theia fallback) and hands it to the language server through `--tsdk=` / `MCX_TYPESCRIPT_PATH`.
  - A tiny stub package (`dist/node_modules/typescript`) forwards `require('typescript')` in both the extension host and the server child process.
  - `@mbler/mcx-core` is now lazy-loaded on first provider call, so the extension host never touches TypeScript during activation.
- **Smarter child-tag completions**: While typing top-down, an unclosed previous sibling (e.g. `<title>text` without `</title>`) no longer hijacks context — completions correctly offer the parent's children inside `<Ui>`, `<Component>`, `<blocks>` groups, etc.
- **Close-tag snippet**: Accepting a tag-name completion inserts `<xxx></xxx>` with the cursor between the tags.

### Fixes

- **"Cannot find name 'Record' / 'Object'"**: The previously bundled copy of TypeScript could not resolve its own lib files, so every ES builtin type was unknown. Resolved by reusing VS Code's TypeScript directly.
- **Extension activation failure** (`Cannot find module 'typescript'` from `vendor-*.js`): eager vendor chunk no longer references TypeScript; it only loads on demand via dynamic import.

### Chores

- Bumped version from `1.1.1` → `1.1.2`
- Server bundle ships `@mbler/mcx-core@0.1.3-rc.16` — adds `<Component>` support for `<blocks>` / `<recipes>` groups and terrain-texture binding
- Packaged size: 152 files / 4.87 MB → 24 files / ~1 MB
